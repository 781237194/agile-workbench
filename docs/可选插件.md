# 可选插件（装了更好，不装不坏）

> 本工作台的团队核心（boot / 派单 / 回执 / 提案 / 评审 / 签字 / apply / 验收 / 看板 / 会话轮换）**不依赖任何可选插件**。
> 没装插件也能跑完整流程；装了记忆 / 视觉 / 搜索等插件，会多出对应能力。缺插件时核心只标 `off`，不报错、不阻断。

## 一、可选插件清单

| 插件（id） | 作用 | 必需性 | 缺了会怎样 | 识别包名 |
|---|---|---|---|---|
| `memory-evolve` | 记忆与待办（跨会话记忆、`memory`/`dtodo` 工具） | 可选 | 记忆校验跳过，标 `memory:off`，核心照常 | `dsh-memory-evolve` |
| `modlens` | 视觉（图片/截图理解） | 可选 | 标 `vision:off`，需要看图的步骤给替代说明，核心照常 | `@liustack/modlens` |
| `web-search-safe` | 联网搜索（只读、安全域） | 可选 | 标 `search:off`，需要联网的步骤可跳过，核心照常 | `web-search-safe` / `@liustack/modsearch` |

> 其余插件（看板、消息中枢、浏览器、皮肤等）由使用者按需安装，清单以本表为准；`team.mjs status` 只固定展示上表三项。

## 二、看当前状态

```powershell
node 团队\工具\team.mjs status          # 末尾「可选插件」段：on/off、版本、数据目录、读取源
node 团队\工具\team.mjs doctor          # 同段 + 把 error（半装/版本不匹配）计入问题
node 团队\工具\team.mjs boot --role pm --project "<项目>"   # 简报里一行降级标记
```

状态含义：

- `on`：已声明依赖且在 profile 的 `dsh.profile.bundles` 里启用（或本地 `plugins/` 目录里有同名包）。
- `off`：未安装，或已安装但未启用；只提示，不算故障。
- `error`：依赖已声明但 profile 里没装到（半装），或版本解析失败；`doctor` 会计入问题，核心仍可用。

读取源（只读，不写 `DSH_HOME`、不加载插件代码）：

1. `<DSH_HOME>/profiles/<profile>/package.json` 的 `dependencies` 与 `dsh.profile.bundles`；
2. `<DSH_HOME>/plugins/<目录>/package.json`（本地 link 插件）；
3. `<DSH_HOME>/profiles/<profile>/node_modules/<包>/package.json`（实际安装版本）。

`<DSH_HOME>` 默认是用户目录下的 `.dsh`；也可用环境变量 `DSH_HOME` 指到别的位置。测试用 `TEAM_PLUGINS_HOME` 指向空目录即可模拟“零插件环境”。

## 三、安装

以 DSH 自带的插件管理为准（命令中的 `<profile>` 换成你的 profile 名，通常是 `desktop`）：

### 3.1 用团队工具实装（推荐，带基线与回滚）

```powershell
# ① 记安装前基线（3 个可选插件的 on/off 与版本）
node 团队\工具\team.mjs plugin baseline --save

# ② 看计划（干跑）：给出要执行的命令与回滚命令
node 团队\工具\team.mjs plugin plan --action install --id modlens

# ③ 确认后执行（必须显式 --yes；找不到 dsh 命令时返回 DSH_CLI_MISSING，不阻断核心）
node 团队\工具\team.mjs plugin run --action install --id modlens --yes

# ④ 复核：基线 vs 当前
node 团队\工具\team.mjs plugin verify
```

### 3.2 手动安装

```powershell
# 记忆
dsh plugin --profile <profile> add dsh-memory-evolve
# 视觉
dsh plugin --profile <profile> add @liustack/modlens
# 搜索
dsh plugin --profile <profile> add web-search-safe

# 装完重启 DSH，然后确认：
node 团队\工具\team.mjs status
```

若你的 DSH 没有 `dsh plugin` 子命令，按 DSH 文档用插件市场/图形界面安装，效果相同。

## 四、卸载

```powershell
# 团队工具（带基线与回滚）
node 团队\工具\team.mjs plugin plan --action uninstall --id modlens
node 团队\工具\team.mjs plugin run --action uninstall --id modlens --yes

# 或手动
dsh plugin --profile <profile> remove dsh-memory-evolve
dsh plugin --profile <profile> remove @liustack/modlens
dsh plugin --profile <profile> remove web-search-safe
```

卸载后重启 DSH；`status` 应显示对应 `off`，核心流程不受影响。

**数据保留**：记忆数据默认在 `<DSH_HOME>/memories`，卸载插件**不会**删除该目录。需要彻底清理时手动备份后再删（本工作台不代删）。

## 五、回滚

```powershell
# 有基线时用团队工具一条命令回滚（基线 off 而当前 on → remove；基线 on 而当前 off → add；一致 → NOOP）
node 团队\工具\team.mjs plugin rollback --id modlens --yes

# 没有基线时：先记状态，再按第四节卸载/安装
node 团队\工具\team.mjs status --json > plugin-status-before.json
```

回滚只影响插件本身；团队状态（`团队/状态/**`）、项目文件、任务与提案都不受影响。

## 六、故障处理

| 现象 | 处理 |
|---|---|
| `status` 显示 `error`，提示“依赖已声明但未安装” | 在 profile 目录执行 `npm install`（或 `pnpm install`）后重启 DSH |
| 装了插件不生效（`off` + “已安装但未启用”） | 把包名加进 profile `package.json` 的 `dsh.profile.bundles`，或用 `dsh plugin` 启用 |
| 版本不匹配/半装 | 卸掉重装；核心不受影响 |
| 数据目录缺失（`memories（未创建）`） | 正常，首次使用会自动创建；不需要手动建 |
| `status` 探测失败 | 输出会写“探测失败…按 off 处理”，不会冒充 `on`；用 `doctor` 复看 |

## 七、双轨测试（无插件 / 有插件结果一致）

```powershell
# 无插件：TEAM_PLUGINS_HOME 指向空目录
$env:TEAM_PLUGINS_HOME = Join-Path $env:TEMP "empty-plugins-home"
node 团队\工具\team.mjs selftest      # 含「零插件」用例：status 全 off、核心流程照常

# 有插件：不设 TEAM_PLUGINS_HOME，用真实 profile
Remove-Item Env:TEAM_PLUGINS_HOME
node 团队\工具\team.mjs selftest
```

两轨的任务 / 提案 / 评审 / 签字 / apply / 验收状态应一致，只允许“可选能力”差异（记忆、视觉、搜索）。selftest 里 `无插件环境` / `有插件环境` / `双轨一致` 三条用例负责这件事。

## 八、安全与边界

- 本工作台**不**读取、**不**打印任何密钥；`status`/`doctor` 只输出插件名、版本、数据目录与读取源路径。
- 可选插件只影响“可选能力”，不影响评审、签字、闸门、apply 等核心闸门。
- 本工作台不代装、不代卸、不代删插件数据；上面的命令都在你确认后手动执行。
