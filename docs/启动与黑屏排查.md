# 工作台启动与黑屏排查（T-ece6 加固后）

> 适用：PM工作台（Electron 壳）。2026-11-14 两次「重启后黑屏」的复盘与加固说明。

## 一、正确启动方式

```bat
start.cmd                  :: 正常启动（有残留主进程时只提示，不启动）
start.cmd --check          :: 只检查：路径 / electron 是否存在 / 有没有残留主进程
start.cmd --kill-orphans   :: 先清掉本工作台残留主进程，再启动
npm start                  :: 等价启动（会显示完整报错）
```

**不要**用相对路径直接跑 `node_modules\electron\dist\electron.exe .` ——
那样起的进程命令行里没有全路径，脚本按路径过滤时**杀不掉**，会变成占着单实例锁的僵尸进程。

## 二、今天黑屏的真实原因

1. 某次用相对路径直接起 Electron，留下一个「僵尸主进程」；
2. 它一直持有 Electron **单实例锁**；
3. 之后每次 `start.cmd` 都是「拿锁失败 → 静默 `app.quit()`」；
4. 表现为：窗口没了 / 黑屏 / 只有 gpu、utility 两个 helper 进程，**主进程秒退**。

侧栏「CPU/内存/GPU」那一整条消失是另一件事：侧栏被隐藏（`awb.sidebar`），点标题栏 `◧` 恢复。

## 三、加固后的行为

| 场景 | 现在的行为 |
|---|---|
| 路径 | `start.cmd` 内所有路径都由 `%~dp0` 派生为**绝对路径**；Electron 用绝对路径启动 |
| 启动前 | 调用 `scripts\start-guard.ps1` 找「本工作台目录下、不带 `--type=` 的 electron 主进程」 |
| 找到残留 | **只提示、不启动**，并打印 PID；用户确认后跑 `start.cmd --kill-orphans` |
| 锁冲突 | 主进程打 `SINGLE_INSTANCE_LOCK_DENIED {at,userData}` 日志，并弹一次人话提示（不再静默退出） |
| 失败退出 | 打印退出码与人话排查建议，退出码 2（有残留未启动）/ 1（其他启动失败） |

## 四、黑屏三步排查

```bat
start.cmd --check
```

1. 看 `mainPid`：有 PID → 说明有实例占着锁。任务栏有窗口就切过去；没有就 `start.cmd --kill-orphans`。
2. 看 electron 是否存在：缺失就先 `npm install`。
3. 还起不来 → 看日志关键字：
   - `SINGLE_INSTANCE_LOCK_DENIED`：锁被占（本文件第三节）；
   - `ROUTE_DAEMON_*`：路由守护拉起/退出；
   - `QUEUE_FILE_BROKEN` / `DECISION_BOX_BROKEN`：派生文件损坏，界面会降级显示。

## 五、给测试/复验的命令

```bat
start.cmd --check            :: 应输出 APP_DIR / electron 路径 / 残留主进程结论，exit 0
start.cmd --kill-orphans     :: 应先打印 [清理] PID，再正常启动
```

断言脚本：`node scripts/test-start-guard.cjs`（只读检查 start.cmd 与 guard 脚本的关键约定）。
