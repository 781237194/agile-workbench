# 测试与沙盘：保留策略与清理入口

> 依据：B-20261117-140928-b51b（Owner 直接反馈「工作区里多了很多测试项目」）。
> 一句话：**沙盘必须可清理；要保留就得显式说理由，并且能一次清干净。**

## 1. 为什么要有这篇

`_tmp/` 曾累积 700+ 个残留沙盘目录（`c72a-batch2`、`decision-box-ui`、`handover`、`4761-migrate-*` …），
在 Owner 的工作区里看起来像一堆「测试项目」。根因不是某一个脚本，而是**没有统一的清理入口与保留策略**：

- 大多数脚本用 `mkTempSandbox`（退出自动删），但仍有脚本用固定名目录、或崩溃/被 kill 时来不及清理；
- 取证时用 `TEAM_SB_KEEP=1` / `--keep` 保留沙盘，事后忘记删；
- 没有「谁该留、留多久、怎么删」的成文口径。

## 2. 写新测试脚本时的硬规矩

1. **默认用 `scripts/lib/sandbox-dir.cjs` 的 `mkTempSandbox('<短名>')`**：每次运行唯一目录，进程退出自动 `rmSandbox`（Windows EPERM 有重试）。
2. 必须用「固定名目录」时（极少数：需要可预测路径给外部工具引用），脚本结尾或 `process.on('exit')` 里自己清理，并支持 `AWB_KEEP_SANDBOX=1` 保留排障。
3. **证据不要写进沙盘**：证据文件一律落 `项目/<项目>/<角色>/产出/证据-*/`。如果历史脚本把证据写在沙盘里（如 `test-fc24-signed-channel.cjs` 的 `_tmp/fc24-signed/run-fc24.json`），
   必须在脚本注释里写明「本沙盘保留证据、不自动清理」，并在退出时打印保留路径。
4. 沙盘里出现「真实 团队.json / workbench.json」相关断言时，沿用 `TEAM_ROOT` + `TEAM_PROJECTS_ROOT` + `TEAM_SELFTEST=1` 三件套隔离（沙盘名册 sessionId 清空）。

## 3. 统一清理入口

```bash
node 团队/工具/team.mjs tmp prune                         # 默认 dry-run：只列候选，不删
node 团队/工具/team.mjs tmp prune --yes                   # 真删（删前写审计）
node 团队/工具/team.mjs tmp prune --keep handover,8947-*  # 白名单：精确名或末尾 * 前缀
node 团队/工具/team.mjs tmp prune --minutes 120           # 阈值（默认 60 分钟）
node 团队/工具/team.mjs tmp prune --root <目录>           # 指定别的根（夹具/排障）
node 团队/工具/team.mjs tmp prune --json                  # 机器可读结果
```

行为（写死在 `团队/工具/lib/tmp-prune.mjs`）：

- **默认 dry-run，`--yes` 才删**；`--dry-run` 与 `--yes` 互斥。
- 只处理 `_tmp` **顶层子目录**；**根下的文件/脚本一律不删**（`.cjs`/`.mjs`/`.json`/日志等）。
- 「未修改超过 N 分钟」按 **递归最新 mtime** 判定：长跑沙盘即使顶层目录 mtime 旧，只要里面还在写文件就保留；
  递归扫描深度 6、条数上限 5 万，超限的目录按「保留」处理（宁可不删）。
- `--keep` 支持精确名与末尾 `*` 前缀通配。
- 删除前先 append 一行「意图清单」，删完再 append 一行「结果」，写到
  `团队/状态/项目/<项目>/沙盘清理.jsonl`（append-only，可回查谁在什么时候删了哪些）：
  - `{"action":"tmp_prune","at":…,"root":…,"minutes":60,"keep":[…],"beforeDirs":N,"candidateCount":M,"candidates":[…]}`（删前）
  - `{"action":"tmp_prune_done","at":…,"removedCount":M,"removed":[…],"failed":[…],"afterDirs":K}`（删后）
- 输出含「清理前后顶层目录数」；验收/发版记录直接摘这两行即可。

## 4. 保留策略

| 项 | 口径 |
|---|---|
| 默认阈值 | 60 分钟（递归最新 mtime） |
| 白名单 | `--keep`，精确名或 `前缀-*`；长期保留的沙盘写进命令而不是改代码 |
| 根下文件 | 永不删除（脚本/日志/JSON 留在 `_tmp/` 根） |
| 异常目录 | 递归扫描超限 → 保留（`SCAN_TRUNCATED`） |
| 符号链接 | 保留（`SYMLINK`），不跟随删除 |
| 审计 | 删前一行、删后一行，`团队/状态/项目/<项目>/沙盘清理.jsonl` |
| 何时跑 | 发版前必跑 dry-run；日常在 `_tmp` 顶层目录 >50 或体积 >10GB 时跑 |

> ⚠️ 有人正在跑沙盘时尽量别 `--yes`：60 分钟递归保护能挡住活跃沙盘，但**长跑 >60 分钟且中途不写文件**的极端场景仍需用 `--keep` 点名保留。
