# 测试环境（沙盘）使用说明 · R-20261115-030035-7841

> 一句话：**换人/轮换、名册与铁律变更、消息与唤醒、迁移归档、门禁矩阵、破坏性脚本这 6 类测试，一律在 `.sandbox/<run-id>/` 里跑**；真实团队状态、真实工作台数据、真实代码工作树都不动，并用「沙盘标记探针 + 真实文件哈希 + git status/HEAD」三重断言证明。
> 代码：`scripts/sandbox/run.cjs`（沙盘 CLI）、`scripts/sandbox/cases/*.cjs`（六类可跑示例）、`scripts/test-sandbox-7841.cjs`（AC1–AC8 断言）。

## 一、一条命令跑通（新人照抄）

```bat
:: 1) 建沙盘（最小快照，约 1 秒）
node scripts\sandbox\run.cjs seed --root .sandbox\sb-1

:: 2) 在沙盘里跑一条会改状态的用例（rotate 换人）
node scripts\sandbox\run.cjs run --root .sandbox\sb-1 --case 01-rotate

:: 3) 证明生产零改动（漏了会 FAIL，不会静默）
node scripts\sandbox\run.cjs verify --root .sandbox\sb-1

:: 4) 按保留策略清理（失败运行无条件保留 + 最近 3 次成功）
node scripts\sandbox\run.cjs clean --dry-run      :: 先看计划
node scripts\sandbox\run.cjs clean               :: 真删
```

**从零到可跑 ≤ 3 分钟**（AC4）：本机实测 seed ≈ 0.7 秒、单条用例 1–2 秒；断言脚本 `node scripts\test-sandbox-7841.cjs` 会打印实测耗时并卡 180 秒上限。

## 二、隔离变量表（缺一就可能漏到真实路径）

| 变量 | 沙盘值 | 为什么要它 |
|---|---|---|
| `DSH_HOME` | `.sandbox/<id>/dsh` | 独立 profile/会话；沙盘不复制也不读取真实 `~/.dsh/.credentials.yaml` |
| `DSH_PROFILE` / `DSH_PROFILE_DIR` | `sandbox` / `.sandbox/<id>/dsh/profiles/sandbox` | 防止继承真实 desktop profile |
| `TEAM_ROOT` | `.sandbox/<id>/团队` | 团队名册/邮箱/启动令牌/锁 全在沙盘 |
| `TEAM_PROJECTS_ROOT` | `.sandbox/<id>/团队/状态/项目` | 项目状态根（工作流/任务/评审代管） |
| `TEAM_WORKBENCH_JSON` | `.sandbox/<id>/data/userdata/workbench.json` | **最易漏的一处**：`session rotate` 的“第三/四处映射”写它，不设就写进真实 `data/userdata/workbench.json`（本需求实测踩到） |
| `AWB_DATA_DIR` | `.sandbox/<id>/data` | 工作台 store 独立 |
| `TEAM_SELFTEST` | `1` | 双保险：沙盘 send/唤醒不投真实角色（B-3c03） |
| `SANDBOX_MARKER` / `SANDBOX_MESSAGE_MARKER` | 固定探针串 | 泄漏探针；出现在真实文件/邮箱 = `SANDBOX_LEAK` |

被**剥离**的真实变量（不传给子进程）：`TEAM_*`、`AWB_*`、`DSH_SESSION_ID`、`DSH_PROFILE*`、`DSH_WEB_URL`。
理由：`DSH_SESSION_ID` 会被 boot 当成本机会话 id（沙盘会绑到真人会话）；`DSH_WEB_URL` 会让 `DshClient` 打到真实实例。

## 三、子命令

| 命令 | 作用 |
|---|---|
| `seed --root .sandbox/<id> [--project 名称] [--full]` | 最小快照：`团队.json` + `工作流.json` + `任务/*.json`（三件必带），外加项目登记/评审代管/决策箱与**项目文档最小集**；清空 `members[].sessionId`；项目快照 `path` 指向沙盘（防 rotate 写真实 `团队会话.json`）；写 `sandbox.json`（隔离根、真实文件基线、git 基线、探针） |
| `run --root <id> (--case <用例> \| -- <命令>)` | 在隔离环境执行。前后比对 `git status --porcelain` 与 HEAD，代码工作树被改 → `SANDBOX_CODE_DIRTY`；记录 `runs[]` |
| `verify --root <id> [--strict] [--assert-code]` | ①探针泄漏（**无条件 FAIL**）②真实文件 sha256/mtime 漂移（默认只报告，`--strict` 判 FAIL）③git 代码工作树：HEAD 变化或**沙盘自有路径**（`.sandbox/_tmp/data/项目/团队状态`）被写脏 → FAIL；`src/scripts/docs` 的改动默认只作 `external` 报告（本项目多角色并行编辑共享工作树），加 `--assert-code` 或 `--strict` 才算 FAIL ④最小快照三件是否齐 |
| `snapshot --root <id>` | 只读检查最小快照三件 |
| `worktree --root <id>` | `git worktree add .sandbox/<id>/code <HEAD>`：验代码改动走 worktree，主工作树保持干净 |
| `clean [--root <id> \| --all --yes] [--dry-run] [--keep 3]` | 保留策略：失败无条件保留 + 最近 N 次成功；`--all` 必须 `--yes` |
| `list` | 列出所有沙盘与运行状态 |

退出码：`0` 成功 ｜ `2` 用法 ｜ `3` `SANDBOX_PATH_OUTSIDE` ｜ `4` `SANDBOX_LEAK` ｜ `5` `SANDBOX_SOURCE_MISSING` ｜ `6` `SANDBOX_DIRTY_ROSTER` ｜ `7` `SANDBOX_CODE_DIRTY` ｜ `8` `SANDBOX_SELFTEST_MISSING` ｜ `9` `SANDBOX_SNAPSHOT_INCOMPLETE` ｜ `10` `SANDBOX_CLEAN_NEEDS_CONFIRM`。

## 四、六类必须进沙盘的测试（各 1 例，已可跑）

| 类别 | 用例 | 断言要点 |
|---|---|---|
| ① 换人 / `session rotate` | `--case 01-rotate` | boot 发令牌 → rotate 到沙盘标记会话；名册 / 轮换记录 / 沙盘 workbench 三处都变 |
| ② 名册 / 角色卡 / 铁律变更 | `--case 02-rules` | 改沙盘团队宪法 → 旧令牌 `RULES_CHANGED`；改名册成员 → `rulesHash` 变化、简报显示名跟随 |
| ③ 消息发送与唤醒 | `--case 03-message` | 沙盘内 send 到 pm 只落沙盘邮箱；名册无真实 sessionId |
| ④ 迁移 / 归档 / 清理 | `--case 04-archive` | PM `session archive --self` 落沙盘 `会话归档/`；有未闭环任务的角色归档被 `TASK_OPEN` 拒 |
| ⑤ 权限与门禁矩阵 | `--case 05-gate` | `QUEUE_FORBIDDEN` / `DECISION_BOX_FORBIDDEN` / `ROLE_NOT_ALLOWED` / Owner 决定必须本机确认 |
| ⑥ 破坏性脚本 | `--case 06-destructive` | 批量写 20 个任务、批量删、写坏工作流模拟崩溃留脏，全部只影响沙盘 |

**不需要沙盘的**：只读查询、单文件格式校验、无副作用的解析与渲染（可在生产只读跑）。

**代码工作树的三分口径**（多角色并行开发的现实）：

| 级别 | 判据 | 何时用 |
|---|---|---|
| 硬判（FAIL） | HEAD 变化；或 `.sandbox/_tmp/data/项目/团队状态` 被写脏 | 永远生效 |
| 软判（只报告 `external`） | `src/scripts/docs` 的改动——可能来自别的角色在同时编辑 | 默认 |
| 严格（FAIL） | 连 `external` 也算脏 | `verify --assert-code`（AC7 断言）、`verify --strict`，或 CI/无人窗口 |

> 断言脚本 `scripts/test-sandbox-7841.cjs` 共 **56 项**（AC1–AC8），实测 56/56 PASS。

## 五、禁止事项（踩过就记一次）

1. **禁止在沙盘里改真实工作树源码**：四类变量隔离的是**数据**，代码仍是同一工作树。要验代码改动，用
   `worktree --root <id>` 检出独立副本，再 `run --in-worktree`；主工作树被改会直接判 `SANDBOX_CODE_DIRTY`。
2. **禁止把真实 `团队/` 整目录复制进沙盘却不清 `sessionId`**（B-3c03 事故）。
3. **禁止漏 `TEAM_WORKBENCH_JSON`**：`session rotate` 会把新会话 id 写进真实 `data/userdata/workbench.json`（本需求实测泄漏一次，已修复并列入断言）。
4. **禁止在沙盘里指向真实邮箱/真实 GUI 端口**：`DSH_WEB_URL` 一律剥离，`DshClient` 只允许在真实终端里对真实实例使用。
5. **禁止 `clean --all` 不加 `--yes`**（脚本会直接拒，退出码 10）。

## 六、B-3c03 事故（反面案例）

2026-11-15 复制真实 `团队/` 建沙盘做测试时，没有清 `members[].sessionId`，也没开 `TEAM_SELFTEST=1`。沙盘里一条 `send` 按名册找到了**真实 PM 会话**并投递了一条「Owner评审：通过」——**消息不可撤回**。
现在沙盘用三道保险挡住这类事：
1. `seed` 把 `members[].sessionId` 全清空，并二次校验（残留即 `SANDBOX_DIRTY_ROSTER`）；
2. `run` 强制 `TEAM_SELFTEST=1`；`--no-selftest` 时会改状态/发消息的用例直接拒跑（`SANDBOX_SELFTEST_MISSING`）；
3. `verify` 用固定探针串扫真实名册/邮箱/workbench/工作流，命中即 `SANDBOX_LEAK`（无条件 FAIL）。

## 七、清理与最小快照（AC8）

- **保留策略**：`.sandbox/` 下**失败运行（`run.json` 里 `ok=false` 或崩溃）无条件保留**；成功运行按创建时间**保留最近 3 次**（`--keep N` 可调），其余删除。
- **最小快照三件**（缺一即 `SANDBOX_SNAPSHOT_INCOMPLETE`）：`团队/状态/团队.json`、`团队/状态/项目/<项目>/工作流.json`、`团队/状态/项目/<项目>/任务/*.json`。不复制产出/证据/备份等大目录（避免沙盘变成第二份真相）。
- **再启动验证**：用保留目录直接 `run --case 07-restart`，断言能读到需求（72 份需求文档）/任务（591）/工作流（70 条需求行）并再次 boot——不是空壳。
- **`--all`**：`clean --all` 不带 `--yes` 直接拒（退出码 10），带 `--yes` 才清全部。

## 八、已知边界

- 真实工作台/团队实例运行时会在后台写 `workbench.json`、`团队.json`，所以 `verify` 的**哈希漂移默认只报告**（噪声）；**泄漏以探针为准**。无人使用实例时可加 `--strict` 让漂移也 FAIL。
- 沙盘 `项目.json` 的 `path` 指向沙盘快照，`dshWorkspaceId` 被删除（避免 sandbox 里 create 会话打到真实工作区）。
- 沙盘没有 `~/.dsh` 凭据与 GUI 端口：`session rotate` 必须用 `--session <id>`（配合 `TEAM_DSH_FAKE` 提供会话列表），不能自动建会话。
- `--full` 仍保留（整目录复制），只在排查历史邮箱/备份时用；日常一律最小快照。
