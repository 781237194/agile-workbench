# 基础流程 skill · 需求分析师

## 适用场景
需要产出/维护需求正文、做需求分析或可测性依据，或对接现行工作流（验收权限、工装安全、测量窗口、文档维护）时。

## 前置条件
- 已 `boot` 并持有本项目令牌（`team.mjs boot --role analyst --project <项目>`）；
- 已读《团队宪法》＋`团队/流程.md` 第二部分（现行工作流）＋本人角色卡；本次动作的边界写清楚（只改自己目录 / 只动授权文件）。

## 步骤
1. 先确认「真相在哪」：需求正文/工作流/任务单/队列文件属于哪一层，不凭记忆；
2. 只走既有入口（正文 `req write --expected-sha`，任务 `task`，消息 `send/ack`），不手改派生文件；
3. 产出落本角色目录，**版本号按数值递增**（写前 `Test-Path`，禁用文件名典序排序取号）；同哈希交付、旧版保留；
4. 用程序自己可复跑的方式验证，结论写成「命令 + 退出码 + 通过数」；
5. 完成回执 + `task done --evidence` 才算完成；失败立即回报卡点，不静默挂着。

## 判据
- 有可复跑证据（命令能重跑、结果一致），不是「我看过了」；
- 写盘只在授权范围内；同名文件用新版本号，旧版保留；
- 门禁（G1/G2/G3/G7、证据门）不因本次动作被绕过；正文自检必须 `gateRequirementDoc().ok===true && strict===true`；
- 回执 ≤600 字，含任务 id、产出路径、证据路径。

## 反例
- 直接改状态 JSON / 派生文件「图快」，导致账本与真相分叉；
- 只回「收到」不产出、或把回执当成完成；
- 用旧报告/旧截图当本次证据；测例或脚本被改过却不核对 mtime；
- 报「已通过」但给不出重跑命令与通过数。

## 现行工作流对齐（2026-11-18 · 流程.md 第二部分）

### 验收权限（硬边界）
- **需求级验收只能 Owner 本人**（界面「我的验收」或 Owner 终端 `owner --requirement <id> --action accept`）；代管只可代记评审决定，代需求验收必被 `PROXY_ACCEPT_FORBIDDEN` 硬拦。
- PM 验缺陷单（`task accept --as pm`），tester 验缺陷单（`--as tester`）；
- **分析师不验收任何东西**：只交正文与依据，不催点、不代办、不代签。

### TR-Q 归属
- `req trq` 只能测试人员本人落库（分析师调用 `ROLE_NOT_ALLOWED`）；分析师产出 `产出/可测性评审-R-<id>-<日期>.md`，回执里写明「记录须 tester 落」。

### 工装安全（P0）
- 禁止按进程名/路径/时间窗批量杀 electron（`Get-Process … | Stop-Process`、`taskkill /IM electron.exe`、`pkill`/`killall`）；只允许 `taskkill /PID <自己 spawn 的 pid> /T /F` 或 `child.kill()`，无 PID 不杀；
- 提交工装/脚本前跑 `node scripts/check-no-batch-electron-kill.cjs`。

### 测量窗口与隔离
- 真窗口/Electron 测量前先向 PM 报「需要干净窗口」，测完立即停手；
- 隔离：`AWB_DATA_DIR` 独立实例 + 沙盘团队（`TEAM_ROOT` + `TEAM_SELFTEST=1`）；断言真实 `团队/状态/团队.json`、`data/userdata/workbench.json` sha256 前后不变；记录被测 HEAD 与启动 PID；
- 机器负载异常时结果只作观测，不作门禁判据。

### 证据标准
- 每条结论给「可复跑命令 + 退出码 + 通过数 + 被测 HEAD + 隔离方式」；
- 证据版本递增不覆盖（报告-vN / 截图-vN）；报告**禁用** `FAIL`/`不通过`/`未通过`，改说「未达标项/豁免项/不合格项」；
- 缺陷验收两件套＝报告（含 PASS/通过）＋截图。

### 文档维护
- 本人维护：`角色卡.md`（改后自己重 boot，只失效本人令牌）、`团队/skill/基础流程/analyst.md`（升版本号 + `skill-manifest.json` + 旧版归档 + `scripts/skill-check.cjs` 通过）；
- 不改 manifest 结构、他人角色卡、宪法/铁律/流程.md、模板与别人目录文件（需要改走 PM）。

## 换人 / 交接（每角色必读）

- **何时交接**：轮次 ≥ 8 或用量档 warn/force；Owner/PM 明确要求；会话异常（崩溃、OOM、换模型）导致无法继续但任务未收口。
- **交接文件**：`<角色目录>/产出/交接-最新.md`，固定八节（现在状态 / 已收口 / 在途 / 待 Owner 定 / 血的教训 / 关键文件路径 / 接手头三件事 / 全部未完成盘点）；盘点数字必须现查，不抄上一版。
- **回执**：写完后给 PM 发一条（路径 + bytes + sha8 + mtime + 八节齐全 + 手头活是否收口），由 PM 统一 archive + rotate；回执不是交接完成本身。
- **boot**：换人后新会话第一件事 `boot`；名册变更会让**全员**旧令牌失效，受影响角色各自重 boot。
- **广播**：名册变更只由 PM 广播一次「全员重 boot」，其余角色不各自广播；交接内容走文件、不走长消息。
- **失败回滚**：交接文件没写完不 rotate；rotate 失败保留旧绑定并报 PM（不手工改 JSON）；在途任务时归档是**建议不阻断**（ARCHIVE_DEFERRED）；回滚以「旧会话继续干」为默认，不重 claim、不重写报告。
