# 01 · 会话与必读

## 一、一个角色 = 一个会话

- 同一工作区（`<工作区根目录>`）下开多个 DSH 会话，每个会话只认一个角色。
- 角色：`pm` / `product` / `analyst` / `programmer1` / `programmer2` / `tester`。
- 会话标题、角色卡、启动卡见 `角色\_索引.md`、`角色\_启动卡.md`。
- 一键建会话：工作台顶栏「建团队」按钮，或 `node 团队\工具\launch.mjs --project <项目>`。

## 二、boot（每轮第一件事）

```powershell
node 团队\工具\team.mjs boot --role pm --project 团队工作台改造
```

boot 会：

1. 读 `团队宪法.md`、`项目铁律.md`（项目目录优先）、`角色\<role>.md`、`项目索引.md`；
2. 计算四样哈希 + 成员表哈希 → `rulesHash`；
3. 写启动令牌（默认 30 分钟），记录本次“已读索引”回执；
4. 打印未读消息、待办任务、待审提案、授权、锁、下一步。

## 三、令牌规矩

- 所有写操作都要带 `--boot <令牌>`：`send / ack / task / req / propose / review / sign / apply / grant / find`。
- 令牌过期 → `BOOT_EXPIRED`；角色/项目不符 → `BOOT_ROLE_MISMATCH` / `BOOT_PROJECT_MISMATCH`。
- 宪法/铁律/角色卡/成员表一变 → `RULES_CHANGED`，旧令牌立即作废，重新 boot。
- 没有令牌不执行；不要拿别人的令牌。

## 四、先读索引，再找文件（死规矩）

1. `boot` 已经把项目索引读进令牌（记录 `projectIndexHash`）。
2. 找文件只用：

```powershell
node 团队\工具\team.mjs find --boot <令牌> --q 关键词
```

3. `find` 只查 `项目索引.json`；索引在 boot 后变了 → `INDEX_CHANGED`，重新 boot。
4. ⛔ 跳过索引直接 `glob/grep`/翻目录 = 违规；找不到时先 `index` 重建，再 `find`。

## 五、会话绑定

- **每个工作区独立建六角色会话，sessionId 是动态值，不能写死在角色卡/项目文件里。**
- `团队\状态\团队.json` 的 `members[].sessionId` 只表示**当前工作区**的角色会话；切换工作区时由 `launch.mjs` 重新绑定。
- `团队\状态\会话.json` 记录最近一次建团队结果；真实标题/ID 以 DSH 会话列表和当前工作区为准。
- 同一工作区重复点“建团队”会按标题复用已有会话；不同工作区不会复用其他工作区的 ID。
- 角色卡、项目信息、项目索引只描述角色与文件，不保存固定 sessionId。
