# 02 · 消息、任务、回执、对账

## 一、消息

```powershell
# PM 派单
node 团队\工具\team.mjs send --boot <T> --to programmer1 --subject "任务 T-..." --body "..." --ack
# 收件人
node 团队\工具\team.mjs inbox --boot <T>
node 团队\工具\team.mjs read  --boot <T> --id M-...
node 团队\工具\team.mjs ack   --boot <T> --id M-... --note "已处理：...（≤300字）"
```

- 重要消息带 `--ack`；收到先 `read`，办完 `ack`。
- `ack` 会自动给发件人回一条“回执”消息，并把回执写入 `状态\回执.jsonl`。
- **没有回执 = 没发生**；不认口头汇报。

## 二、任务 / 需求

```powershell
# 需求（产品/PM/需求分析）
node 团队\工具\team.mjs req create --boot <T> --title "..." --priority P1 --acceptance "..." --story "..."
# 任务（关联需求）
node 团队\工具\team.mjs task create --boot <T> --title "..." --priority P1 --requirement R-... --owner programmer1
# 认领 / 完成
node 团队\工具\team.mjs task claim --boot <T> --id T-...
node 团队\工具\team.mjs task done  --boot <T> --id T-... --evidence "C-... / 路径 / verify 输出"
```

- 任务只有 owner 能 claim / done；PM 可改优先级、释放。
- 没有验收标准不开发；没有证据不算完成。
- 需求看板：`team.mjs req list`、`team.mjs board`。

## 三、对账格式（固定）

```markdown
| 项目 | 指标 | 期望 | 实测 | 结果 | 证据 |
|---|---|---|---|---|---|
| 事件链 | seq/prev/hash | 连续 | 128 条 / 0 问题 | PASS | verifyEventChain |
```

- 每行一个检查点；结果只能 `PASS` / `FAIL`；证据写路径/哈希/命令。
- 末尾必须有对账回执：对账人、复核人、结论、备注。
- `team.mjs reconcile` 自动生成该格式；PM 跑，tester 复核签字。
- 回执 ≤300 字；报告 ≤8KB；超限截断并指向 `对账.json`。

## 四、大小限制

| 对象 | 上限 |
|---|---|
| 单条消息 | 600 字 |
| 回执 / 对账回执 | 300 字 |
| 对账报告 | 8KB |
| boot 简报 | 2KB |
| 宪法 / 角色卡 | 4KB |

超限拆条；一件事最多 3 条；不刷屏。
