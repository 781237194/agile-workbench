# 03 · 变更、评审、签字、提交

## 一、唯一路径

```text
propose → show → review → sign → apply
```

没有“直接改一下”；`apply` 是唯一写目标文件的命令，且只有 PM 能执行。

## 二、提案

```powershell
# 1) 写 staged 副本（不是目标文件）
# 2) 记下目标当前哈希（absent=新文件）
node 团队\工具\team.mjs propose --boot <T> --task T-... --title "..." ^
  --file "src/a.mjs=暂存\a.mjs" --expect "src/a.mjs=<当前哈希>" ^
  --rationale "为什么改、怎么验证" --risk normal
```

- `--expect` 必须是你**读到的版本**；读完文件变了 → `STALE_BASE`。
- 目标必须在项目内、在 grant 的 scope 内。
- 风险只能升不能降：normal < sensitive < critical。
- 提案哈希 = 文件 base/new 哈希 + 标题 + 理由 + 作者 + 时间；任何改动都会换哈希。

## 三、评审

```powershell
node 团队\工具\team.mjs show   --boot <T> --proposal P-... --diff   # 记录“已读”
node 团队\工具\team.mjs review --boot <T> --proposal P-... --verdict approve --comments "..."
```

- **先 show 后 review**；不是同一 `proposalHash` 的 show 不算。
- 作者不能审自己；打回必须写 ≥10 字理由。
- normal 至少 1 名非作者评审；sensitive/critical 全体非作者评审。

## 四、签字

```powershell
node 团队\工具\team.mjs sign --boot <T> --proposal P-... --decision approve --note "..."
```

- 签字绑定 `proposalHash + baseHash + newHash`；换版本 = 签字作废。
- 非作者签字前必须有同哈希的 approve review。
- 作者自签只允许 sensitive/critical，且要 `--self`。
- 签字规则：
  - normal：作者 + 1 评审 + PM 签；作者是 PM 时由另一成员签。
  - sensitive/critical：全体成员签 + owner 终端批准。

## 五、owner 终端批准

```powershell
# 必须真人 PowerShell 窗口；无 TTY 会被拒绝
node 团队\工具\team.mjs owner-approve --proposal P-... --project <项目>
# 输入：批准 P-...
```

Agent 的 pwsh 不是 TTY，不能代替 owner 批准。

## 六、提交

```powershell
node 团队\工具\team.mjs apply --boot <T> --proposal P-...
```

apply 会：

1. 重新算提案哈希、核对评审/签字；
2. **CAS**：逐文件比对当前哈希与 baseHash，任何一个变了 → `STALE_BASE`，整单作废；
3. 备份将被写的文件（只备份这几个）；
4. 写目标（临时文件 + rename），逐个核对 newHash；
5. 写提交记录、更新产物版本、重建索引；
6. 失败自动回滚（新文件删除、旧文件恢复），回滚不完整 → `ROLLBACK_FAILED` 立即停手。

## 七、完成

```powershell
node 团队\工具\team.mjs task done --boot <T> --id T-... --evidence "C-..."
node 团队\工具\team.mjs verify
```

- 没有 commit id 的“完成”不认。
- 反方向也要互审：PM 的提案由程序员/测试审，不能只让 PM 审别人。
