# 06 · 风险、DSH 重启、两角色试点、扩编

## 一、风险分级

| 级别 | 范围 | 评审 | 签字 | owner |
|---|---|---|---|---|
| normal | 项目内普通文件 | ≥1 非作者 | PM（作者是 PM 时另一成员） | 不需要 |
| sensitive | 宪法/铁律/角色卡/共享工具/索引/场景/AGENTS/外壳/看板 | 全体非作者 | 全体成员 | 终端批准 |
| critical | DSH_HOME / profiles / 插件 / 重启 / 删除 / 网络 | 全体非作者 | 全体成员 | 终端批准 + 备份 + 回滚演练 |

## 二、DSH 重启（critical）

必须同时满足，缺一不做：

1. 全员评审 + 全员签字；
2. owner 在真实终端 `owner-approve`；
3. 只备份将被写的文件（`profiles\desktop` 三件套等），带时间戳；
4. 写回滚脚本，**先在沙盘跑一遍**；
5. 重启后验证：bundles 数、工具注册、`verify`、`doctor`、看板；
6. 失败立即回滚，不继续。

## 三、两角色试点（先跑通再加人）

试点 = `pm` + `programmer1`，只做一件事：跑通回执 + 签字 + 陈旧拒绝 + 锁争用。

`pilot` 检查 5 项：

1. 消息回执 ≥1；
2. 提案闭环（评审+签字+提交）≥1；
3. `STALE_BASE` 拒绝 ≥1；
4. `LOCK_BUSY` 拒绝 ≥1；
5. `verify` 全绿。

五项全过才允许加人。加人一次只加 1 个，加完重跑一轮 1 写 1 审。

## 四、六角色扩编顺序

1. `tester`（先有独立验证，防止自己批自己）
2. `product`（接优先级/验收）
3. `analyst`（接需求/缺陷闭环）
4. `programmer2`（并行开发，先划清文件边界）

每次加人：

```powershell
node 团队\工具\team.mjs roster add --boot <T> --role tester --name 测试 --reason "pilot 通过"
node 团队\工具\team.mjs board
```

- 新角色先读四样（宪法/铁律/角色卡/索引）再 boot。
- 角色卡、启动卡、授权、看板同步更新。
- 加人后旧令牌因成员表变化自动作废，所有人重新 boot。

## 五、一键建会话

工作台顶栏「建团队」按钮 → 选工作区/项目 → 创建六个会话并发送启动卡。
默认**只建空会话**（不烧 token）；勾选“立即启动”才发启动卡。
命令行等价：

```powershell
node 团队\工具\launch.mjs --project <项目> --workspace "<工作区根目录>" --no-prompt
```
