# 07 · 换人流程（回执驱动）

> Owner 2026-11-18 14:35 定稿口径：**不搞强制换人**。到阈值只提醒；本人写交接并回执 PM；PM 核对后手动换人；**PM 自己的换人由产品执行**。
> 代码落地：`R-20261118-143558-eba2`（回执命令 + rotate 权限 + 回执校验 + 审计）；自动换人停用见 `B-20261118-143542-3594`（auto-rotate 改 remind-only）。

## 一、四步流程

### 第 1 步 · 到阈值先提醒（不换人）

- `session usage` 口径判档：预警（默认 30 万）→ 提醒本人 + PM；强制档（默认 50 万，PM 2 倍）→ 提醒「需要换人」。
- 只发 `session_rotate_warn` 消息与事件；**任何程序都不得自动 rotate**。

### 第 2 步 · 本人写交接并落回执

1. 写 `<角色目录>/产出/交接-最新.md`（八节，照 `项目经理/产出/交接-最新.md` 模板）；
2. 落回执（本人令牌）：

```
node 团队\工具\team.mjs session handover receipt --boot <本人令牌> --role <自己> --project <项目>
```

3. 回执内容：`交接-最新.md` 的 `bytes + sha256`，append 到 `团队/状态/项目/<项目>/交接回执.jsonl`；
4. 给 PM 发消息：subject `交接就绪：<角色> <sha8>`，`type=notice`，正文带文件路径、字节、sha8。

### 第 3 步 · PM 核对并手动换人（普通角色）

```
node 团队\工具\team.mjs session rotate --boot <PM令牌> --role <角色> --project <项目> --reason "..."
```

- rotate 起手先校验：**最新回执存在且 sha/bytes 与磁盘交接文件一致**；不符 → `HANDOVER_RECEIPT_REQUIRED`（`no_receipt` / `file_missing` / `sha_mismatch`），**零副作用**（不改名册、不建会话、不写记录）。
- 再校验接任包必填小节（`HANDOVER_INCOMPLETE`）。
- 成功后写轮换记录，审计含 `actorRole/by=pm`、`receiptId`、`handoverSha256/Bytes/Path`。

### 第 4 步 · PM 自己的换人（产品执行）

1. PM 写 `项目经理/产出/交接-最新.md`，落回执（PM 令牌）：

```
node 团队\工具\team.mjs session handover receipt --boot <PM令牌> --role pm --project <项目>
```

2. PM 把回执（sha8/字节）发给 Owner/产品；
3. **产品执行**（产品令牌，仅可换 PM）：

```
node 团队\工具\team.mjs session rotate --boot <产品令牌> --role pm --project <项目> --reason "PM 到阈值换人（回执 H-...）"
```

4. 审计：`by=product`、`actorRole=product`、`receiptId`、`handoverSha256`；
5. **PM 不能给自己换人**（`tokenRole=pm && role=pm` → `PERMISSION_DENIED`）。

### 收尾 · 换人后

- rotate 既有链保留：写「待启动队列」BQ 拉起新会话 + 广播其余角色重 boot（两条都留）；
- 新会话 boot 后读交接包；其余角色收 `RULES_CHANGED` 后各自重 boot。

## 二、权限矩阵（A 案）

| 令牌角色 | 可换目标 | 说明 |
|---|---|---|
| owner | 任意角色 | Owner 应急通道 |
| pm | 除 pm 外全部 | PM 换普通角色；自己不能换自己 |
| product | 仅 pm | 产品给 PM 换人 |
| 其他 | 无 | `PERMISSION_DENIED` |

- 校验位置：`session.mjs` rotate 分支，**在任何写盘之前**（接任包检查、回执检查、rotateSession 都排它之后）。
- 沙盘：`TEAM_SELFTEST=1` 豁免令牌门；门禁本体用 `TEAM_BOOT_ENFORCE=1` 强制；回执门禁用 `TEAM_HANDOVER_ENFORCE=1` 强制。

## 三、审计字段（写死）

`会话轮换/<role>.json` 与 `会话轮换.jsonl` 每行：

```
actorRole        令牌角色（pm / product / owner / selftest）
by               同 actorRole（不读 --by，防自报）
handoverSha256   交接文件 sha256（与回执一致）
handoverBytes    交接文件字节
handoverPath     项目内相对路径
receiptId        回执 id（H-<ts>-<role>）
receiptAt        回执时间
```

另写 `名册变更.jsonl`：`{at,action:'rotate',by,role,from,to,receiptId,handoverSha256}`。

## 四、失败与恢复

| 情况 | 错误码 | 处置 |
|---|---|---|
| 没落回执 | `HANDOVER_RECEIPT_REQUIRED`（no_receipt） | 先 `session handover receipt` |
| 回执后改了交接文件 | `HANDOVER_RECEIPT_REQUIRED`（sha_mismatch） | 重新落回执（内容变了必须重签） |
| 交接文件缺失/为空 | `HANDOVER_FILE_MISSING` / `HANDOVER_FILE_EMPTY` | 先写交接 |
| 小节不全 | `HANDOVER_INCOMPLETE` | 补齐【在途任务/未闭环事项/最近决策/建议下一步】 |
| 产品换非 PM | `PERMISSION_DENIED` | 只有 PM/Owner 能换普通角色 |
| PM 自换 | `PERMISSION_DENIED` | 走产品执行 |

以上失败均**零副作用**（不改名册、不建会话、不写轮换记录）。
