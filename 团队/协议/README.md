# 团队协议 · 索引

> 每个成员每轮先 `boot`；本目录是细则，宪法和铁律是硬规矩。
> 协议版本：v2 ｜ 2026-10-29

## 一、十步主流程

1. 建会话（按钮 / `launch.mjs`）→ 2. 发启动卡 → 3. `boot` 读四样 → 4. 收 `inbox` / `read` / `ack` → 5. `task claim` / `req` → 6. `find` 查索引 → 7. 写 staged → 8. `propose → show → review → sign → apply` → 9. `task done` + 回执 → 10. `reconcile` / `verify` / `board`。

## 二、文档

| 文档 | 什么时候读 |
|---|---|
| `01-会话与必读.md` | 建会话、认领、boot、索引优先 |
| `02-消息任务回执.md` | 发消息、回执、任务、需求看板、对账格式 |
| `03-变更评审签字.md` | propose / review / sign / apply / 风险分级 |
| `04-锁与版本栅栏.md` | 锁、CAS、旧版本、回滚 |
| `05-授权日志索引看板.md` | grant、日志、索引、看板、verify |
| `06-风险重启扩编.md` | 底层改动、DSH 重启、两角色试点、加人 |

## 三、死规矩（重复三遍）

- **没有回执 = 没发生。**
- **锁只防同时写；版本靠 CAS。**
- **先读索引，再找文件。**
