# 角色索引

> 六个角色 = 六个独立会话（**每个工作区独立创建，sessionId 不写死**）。
> 每轮第一件事读《项目铁律.md》；只有被老板/PM 按任务叫到才启动。
> 没有启动令牌不执行写操作；**中文思考、中文回复、中文写文档**。
> 派单闭环：`ack`=已回执（收到/认领）→ 执行正文 → 产出写本角色目录 → 完成回执 + `task done --evidence`=已完成；只 ack 不算完成。

| 角色 id | 名称 | 角色卡 | 一句话职责 | 默认会话标题 |
|---|---|---|---|---|
| `pm` | 项目经理 | `角色\pm.md` | 建需求/建任务/派单/跟进完成；写项目信息、催回执、批复、签字/apply、维护索引 | 团队·项目经理 |
| `product` | 产品设计师 | `角色\product.md` | 产品+架构：拆解评审、用户故事/流程类图/架构/竞品/优先级/验收 | 团队·产品设计师 |
| `analyst` | 需求分析师 | `角色\analyst.md` | 需求拆解与评审、场景缺陷闭环/可行性/验收标准/一需求一文件 | 团队·需求分析师 |
| `programmer1` | 高级程序员 A | `角色\programmer1.md` | 只做本职：开发 A / 提 proposal / 互审（不越界定需求/结论） | 团队·高级程序员 A |
| `programmer2` | 高级程序员 B | `角色\programmer2.md` | 只做本职：开发 B / 提 proposal / 互审（不抢同一文件） | 团队·高级程序员 B |
| `tester` | 测试人员 | `角色\tester.md` | 只做本职：测试/独立验证/缺陷闭环/对账复核/签字 | 团队·测试人员 |

## 启动方式

见 `角色\_启动卡.md`。**不再群发启动卡**：建团队只建空会话；老板先找 PM 说需求，PM 写完项目信息和任务分配后，用 `send --ack` 逐个唤醒。
实际会话 ID 只以 `团队\状态\会话.json` 和当前工作区为准。
> 已有项目目录里的角色卡是旧版时，以《团队宪法》《项目铁律》和 boot 简报为准；新建项目按新版角色卡生成。
